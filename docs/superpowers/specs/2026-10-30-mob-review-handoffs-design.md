# Compact mob-review handoffs

Reduce repeated context and validation while preserving independent lenses, model tiers, evidence standards, consent, and user control over fixes.

## Approved direction

Prepare one review package with the exact scope, relevant requirements, diff, and existing test evidence. Include scoped committed, staged, unstaged, and untracked changes. Identify the reviewed inputs so later results cannot silently apply to changed code.

Give each lens a fresh context and a short brief. Keep other reviewers' conclusions out of independent passes. Let reviewers inspect dependencies when needed to evaluate a concrete risk.

Require compact results with scope, completion status, checks, evidence-backed findings, and gaps. Keep findings unlimited. Strong triage records the reason for each dropped or downgraded blocker.

Reuse matching test evidence and completed review results. Resume unresolved work after interruption. After authorized fixes, review the delta and affected dependencies with every affected lens.

Keep project files, index, and refs unchanged during review. Permit temporary review artifacts outside the checkout. Preserve inline handoffs when artifact storage is unavailable.

## Limits and validation

Change the skill instructions and their pressure-test evidence. Leave model routing, benchmark prompts, cases, and published results unchanged.

Compare baseline and updated instructions in fresh-context proposed-dispatch tests. Then exercise the updated workflow on a concrete review fixture and inspect the skill change independently. Run repository wiring, prose, diff, and evaluation regression checks.

These checks establish instruction behavior. They do not establish lower token usage or equivalent defect detection in full-repository reviews. Measure those in a separate paired native evaluation before claiming savings.
